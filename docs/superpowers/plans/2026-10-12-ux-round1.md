# UX round 1: implementation brief

Inputs (read all three before touching code):
- `e2e/out/ux/round1/notes-owner-and-tour.md` (owner requirements, first-look notes, corrections)
- `e2e/out/ux/round1/code-audit-findings.json` (59 code-level findings, 4 lenses)
- `e2e/out/ux/round1/screenshot-findings-partial.json` (29 screenshot findings)
- Screenshots: `e2e/out/ux/round1/<profile>/*.png` (desktop300 is the owner's default sidebar; ipad-portrait is the kitchen device; iphone is secondary). Read the ones your package cites.

Context: Obsidian plugin, TypeScript strict, Preact + @preact/signals, CSS in `src/styles` (loaded in `src/styles/index.css` order), unit tests with vitest + jsdom under `test/`. Obsidian's own CSS applies global rules to `button` (`button:not(.clickable-icon)` sets height 30px, white-space nowrap, grey background, box-shadow, centred flex, Obsidian radius; mobile adds `.is-mobile button` rules). The plugin's root element has class `claudsidian-root`; views carry `claudsidian-view`; mobile Obsidian adds `is-mobile` (and `is-phone` on phones) to `body`.

Rules for every package:
- Edit only the files your package owns (listed below). If you need a change in another package's file, write the exact change you need into `e2e/out/ux/round1/handoff-<package>.md` and continue; do not edit the file.
- No git commands. No `npm install`. Do not run the browser harness or the Obsidian driver (they need the sandbox off); run `npx vitest run <your test files>` and `npm run -s typecheck`, and fix only errors in your own files (other packages are being edited concurrently; ignore their errors, note them in your handoff file).
- Keep the markdown rendering through Obsidian's `MarkdownRenderer` (via the facade); do not add dependencies.
- Prefer Obsidian CSS variables (`--background-primary`, `--background-secondary`, `--background-modifier-hover`, `--text-normal`, `--text-muted`, `--text-faint`, `--interactive-accent`, `--text-on-accent`, `--background-modifier-border`, `--radius-s/m/l`, `--font-ui-small/smaller`, `--size-4-*`). No hard-coded colours.
- Touch targets: 44 px on `.is-mobile`, 32 px minimum on desktop. Cooking mode (`.is-cooking` on the view content, font scale via `--claudsidian-scale`) must not overflow horizontally.
- Add or update unit tests for behaviour you change (test files follow source ownership). Keep existing tests passing or update them with the behaviour change explained in the test name.
- When done, return a short structured summary: what changed per file, tests run and their result, anything left for another package (also written to your handoff file).
